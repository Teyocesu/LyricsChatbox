# LyricsChatbox

## v1.0.0 normative final features contract

Four final improvements complete v1.0.0. They add no new providers, playback sources, network services or visual system, and every other contract in this document stays in force. Chrome and YouTube are out of scope, Floating stays unavailable, and Manual messaging and Quick Messages stay removed.

### Guided bug report

- About → Project & tools → Report Issue opens a compact guide window in the Instrumento style instead of opening GitHub directly. The guide explains the steps, collects What happened, What you expected and Steps to reproduce in plain text boxes, and explains how to add a screenshot manually to the GitHub issue. Nothing is captured automatically.
- Diagnostics come only from the existing sanitized export. They are excluded from the report until the user ticks Include diagnostics. Review diagnostics shows the exact text read-only, and Copy diagnostics copies it.
- Copy report puts a structured Markdown report on the clipboard: the three answers, the app version and Windows version, and diagnostics only when included. Copy report and open GitHub copies the same report and then opens the official new-issue page through the existing allowlisted link handler. The report never travels in the URL, nothing is uploaded, and no account, backend or telemetry exists.
- Don't show this guide again is an optional preference, saved as `SkipReportGuide` in `settings.json` and defaulting to off for older files. While it is on, Report Issue opens the new-issue page directly, and an Open report guide button stays in the same row so the guide can always be reopened and the preference turned off.
- The guide is fully keyboard operable: logical Tab order, visible focus, Escape closes it, and focus returns to Report Issue.

### Recent decorations

- The Decorations picker gains a Recent view after Favorites, superseding the v0.7.0 exact navigation list and its exclusion of a recently-used subsystem. It lists the last 16 successfully inserted items, most recent first, without duplicates; reinserting an item moves it to the front. Popular stays the opening view.
- Only a completed insertion into the editor updates Recent. Previewing, selecting, favoriting, cancelling, closing and insertions refused for lack of editor space do not.
- `decorations.json` stores the IDs only, as `RecentIds`, capped at 16 valid unique IDs. Built-in and My item IDs are both allowed. Missing IDs, including deleted My items, are skipped when shown, and deleting a My item also removes it from Recent.
- Older files without `RecentIds` stay readable as an empty Recent. An invalid `RecentIds` list is discarded on read without discarding Favorites or My items. The existing 256 KiB file limit, atomic writes and catalog stay unchanged. Rolling back to v0.7.0 ignores and later drops Recent.

### OSC status and Send test

- Settings → VRChat OSC shows where output is actually sent, from the destination the socket uses, and how that destination was chosen: found with OSCQuery, explicitly set manually, VRChat not detected while automatic (sending to the configured address), or destination unavailable. It never says connected, and it never claims VRChat received or displayed anything.
- It shows the time of the last successful local UDP send in this session, or that nothing was sent yet. A successful send means only that the packet left this computer.
- Send test queues one short fixed message, `LyricsChatbox test message`, after a deliberate click. It goes through the existing scheduler, destination and socket, so the 1.05-second pacing, current destination and receiver changes apply. It is refused while Output is off, explicitly paused or held by Native Chatbox Protection, and a queued test is cancelled if any of those start before it leaves. The test stays visible for 3 seconds, then normal output resumes and the current text is resent; when there is no current text the Chatbox is cleared. Lyrics, profiles, rotation and pause state are never changed. One click sends at most one test, there is no repetition or background testing, and failures are reported plainly.

### Accessibility and keyboard

- Shell, Home, Display, Settings, About, Decorations, the bug report guide and the OSC controls keep a logical Tab order, visible keyboard focus, Enter or Space activation, meaningful accessible names, no needless keyboard stops, and focus restoration after dialogs, including at 820x650.
- No action may sit under the 36-DIP caption band or be reachable only by scrolling behind window controls. Rename at 820x650 is checked against this rule and fixed with the smallest layout or focus change only if it fails.

### Principles

- No repeated cards or rounded containers, glassmorphism, glows, gradient borders, or fake metrics, waves or charts.
- Headings use sentence case: SemiBold in the text color with no rule beneath, at 13 DIP, or 15 DIP for panel titles such as the Home inspector.
- The accent marks selection, progress, primary actions, links and state only. It is never used on titles, dividers or decorative borders.
- Alternative and custom accents recolor everything the accent colors, and the Accent brushes stay dynamic resources.

## v1.0.0 normative Floating compatibility contract

This contract supersedes prior requirements that Floating must remain effective or always reserve two units. It defines the v1.0.0 behavior; the released v0.7.0 remains unchanged.

Loading, selecting, duplicating and saving profiles, changing unrelated settings, and restarting must preserve the stored value, including `true`. No schema change, destructive migration, or replacement of the stored preference with the effective value is permitted. Built-in Minimal retains its preference.
- The shipped v1.0.0 compatibility policy makes the legacy Floating method unavailable for all destinations. It is a release policy, not a claim that the running VRChat build was detected. One small authoritative capability policy derives effective Floating from saved preference AND availability; all composition, fitting, formatting, presentation and UI consumers use that same result. No service hierarchy, version scraping, process/file inspection, remote flags, backend, telemetry or new network dependency.
- While unavailable, automatic output, Preview, Lyric Context fitting, Decorations fit filtering and budget explanations use normal formatting: up to 144 visible UTF-16 units, no U+0003 U+001F suffix, existing grapheme safety and nine-explicit-line limit. Empty/whitespace clears stay empty. Preserve intentional line breaks, indentation, alignment, current-lyric priority and fixed template content; no injected wrapping or replacement control-character trick. Manual ownership, Output/Pause gates, epochs, pacing, retry and dedupe rules remain unchanged.
- Floating remains visible on Display with its saved checked state, but cannot be toggled while unavailable. Label: `Floating`; explanation: `Temporarily unavailable in the current VRChat client.` Supporting copy: `A recent VRChat client change prevents LyricsChatbox's previous compact Chatbox method from working. Your profile preference is preserved.` Keep the explanation accessible even when the checkbox is disabled. The tray Floating action is also visible, unavailable and reflects the saved preference. Profile summaries must distinguish a saved Floating preference from an active effect, for example `Floating unavailable`; they must not imply compact output. Restoring a physically verified compatible method in a future release may reactivate saved preferences without migration; no user override or runtime auto-detection is added now. Another technique would require its own verified budget/contract rather than silently inheriting the legacy suffix.

## v1.0.0 normative Native Chatbox Protection contract (Phase 5A, experimental)

Automatic Chatbox output steps aside while VRChat's own Chatbox popup is open, so LyricsChatbox does not overwrite what the user is typing. It reads undocumented local log lines. It is an unofficial, best-effort feature with no guaranteed detection, intended for VRChat for Windows in Desktop and PCVR. Standalone Quest is not supported. Absence of matching log lines proves nothing: it does not show that the Chatbox is closed or that a VRChat build still writes them.

- **Off by default:** `NativeChatboxProtection` defaults to false and `NativeChatboxCooldownSeconds` to 15, clamped to 5–60. Older settings load unchanged. While off there is no log access and no hold state, and existing behavior is unchanged. Enabling it reads nothing from before the moment it was enabled.
- **Functional states:** NORMAL sends automatic output. CHATBOX_OPEN follows a verified opening line and holds output. WAITING_AFTER_CLOSE follows a verified removal line, also with no earlier open, and holds output for the cooldown; an opening line restores CHATBOX_OPEN. When the cooldown ends the state is NORMAL. UNCERTAIN follows loss of log continuity while CHATBOX_OPEN and keeps the hold until a verified line or Resume now. UNAVAILABLE means VRChat is not running or its log cannot be read; it holds nothing and tells the user that protection is not active. There is no timeout while the Chatbox is known open or uncertain.
- **Session reset:** a change of VRChat process, including exit, ends every hold and clears session state, and output continues with the current nonempty text. Popup state, file position, cooldown and uncertainty are transient and never persisted.
- **Log input:** only the newest `output_log_*.txt` in VRChat's Windows log folder is read, by byte offset, in the background, with bounded reads and bounded lines. Only appended bytes are read. A newer log created while monitoring is read from its start; any other replacement, truncation or disappearance resumes at the current end and never replays history. The log is untrusted: a line counts only if it exactly matches a `Warning` line for `VP Popups_Chat` with `OnPageAddedToStack` or `OnPageRemovedFromStack`. `Keyboard` and `Popups_Keyboard` are ignored. `Finish` is ignored too: a delayed or duplicate one cannot be told from a current one, and every closing observed in the PoC carried a removal line, so a missing removal keeps the hold until Resume now rather than risking a reopened popup. A world can write matching text, so a match is evidence rather than proof.
- **Privacy:** no keyboard capture and no message text. Raw lines are never stored, uploaded or added to Diagnostics, which report only the feature state. No memory reading, injection, hooks, client changes, anti-cheat interference, elevated access or network use.
- **Output priority:** Output Off, then explicit Output Pause, then the native hold, then automatic lyrics. The hold never turns Output on and never ends a Pause. While held, the composition, preview and playback keep running and rotation is frozen. Nothing replays.
- **OSC during hold:** no Chatbox text and no empty text is sent automatically, so the native message is never cleared by this feature. The only intentional exception is the explicit Output Pause action, which keeps its documented Clear.
- **Resume:** release rearms only the current nonempty desired text through the existing scheduler, with its existing rate limit. It sends no history and no empty packet. Real receiver changes keep their existing behavior.
- **Status and override:** the existing Output status, preview ownership and OSC text name the hold. Settings shows the toggle, the cooldown, the detection state, a short explanation and Resume now, which also appears as the sidebar Resume action while held. Resume now releases the hold until the next verified line and never affects Pause or Off.
- **Floating:** the Floating policy is unchanged.
- **Acceptance:** with the feature off there is no log access. With it on, an opening line stops all automatic packets; a closing line starts the cooldown; an opening line during the cooldown holds again; a missing closing line never resumes by itself; lost or replaced logs are safe; unrelated or spoofed-format lines change nothing; resume sends no empty or stale packet; Off and Pause keep precedence; rotation stays frozen. Synthetic and loopback evidence does not count as a real VRChat pass: Desktop integrated QA decides acceptance for v1.0.0. The product owner waived PCVR integrated QA for this release, so PCVR stays experimental and unverified for this implementation.
- **Out of scope:** Quick Send, the Settings redesign, standalone Quest, other players' Chatbox state, and any promise that VRChat keeps these log lines.

## v0.7.0 normative proposal — Composition, Decorations and Daily-Use Clarity

v0.7.0 is a Windows-only .NET 10 WPF minor release with exactly four product areas: Display/composition simplification, a local Decorations picker, profile-owned Rotating Messages, and an About/sidebar/Output presentation cleanup. It preserves the current local-first architecture and the pipeline Playback → Track identity → Lyrics → Composition → Formatting → Scheduler → OSC. It adds no account, backend, telemetry, cloud state, runtime scraping, arbitrary player, plugin system, scripting engine or generic Chatbox framework.

Implementation status: Phases 0–5 are implemented on the v0.7.0 development branch. The product owner physically approved the final Decorations picker, Display polish and About/sidebar/Output presentation. The current visual design is accepted for v0.7.0.

### Display and composition

- Display answers one question — “What should VRChat show?” — through six visible concepts: Profile, Composition, contextual Status messages, contextual Lyric Context, Presentation and Live Preview. Existing presets and profile behavior remain available; Custom is the primary advanced editor rather than a separate template ecosystem.
- The supported composition tokens remain `{lyrics}`, `{title}`, `{artist}`, `{album}`, `{time}`, `{message}`, `{elapsed}` and `{duration}`. Each token is an accessible insertable chip. Activating a chip replaces the current selection, or inserts at the current caret when the selection is empty, subject to the editor's existing 512 UTF-16-unit maximum. Focus returns to the editor and the caret moves after the inserted token. Substituted values continue to be single-pass data and are never reinterpreted as template syntax.
- Status/Rotating Messages controls are shown only when the effective composition consumes `{message}`: always for Status / Time, and for Custom only when its template contains that exact supported token. Other presets show no large active no-op editor. A concise disabled explanation may tell the user to add `{message}`.
- Lyric Context cards remain visible on Home and Display so dashboard layout and discoverability are stable. Their controls are enabled only when the effective composition consumes `{lyrics}`; otherwise the saved mode remains unchanged and a concise explanation identifies either a Custom template missing `{lyrics}` or a composition that does not use lyrics. The same derived-state refresh runs during cold initialization, profile selection, preset changes and template edits.
- Left, Center and Right remain presentation choices. Center and Right continue to be approximated with ordinary spaces and are never described as pixel-perfect VRChat alignment. Floating/Compact also remains a presentation choice and retains the existing 142-visible-unit budget plus suffix; normal output retains 144 visible UTF-16 units. Live Preview remains the actual formatted visible payload, not an optimistic editor rendering.

### Insert / Decorations

- The three editor-specific ASCII selectors are replaced by one reusable picker launched by buttons labeled `Decorations menu` and titled `Decorations`, used by Custom composition, Status/Rotating Message editors and the Manual draft. One insertion routine owns caret/selection replacement, maximum-length checks, focus restoration and caret restoration; no editor-specific copy exists. The final picker action remains `Insert`.
- Left navigation is exactly Favorites, Popular, Symbols, Text Art, Kaomoji, Dividers, Frames, Hearts, Music and Status; Popular is explicitly the opening view even though Favorites is listed first. My items opens as a footer action in the same modal and retains add/edit/delete/favorite behavior. Suggested and all recommendation logic are absent. Search performs a direct `OrdinalIgnoreCase` in-memory match over Name, Content, Kind and optional built-in Group/SearchTerms. The exact Kinds remain `Symbol`, `TextArt`, `Kaomoji`, `Divider`, `Frame`, `Heart`, `Music` and `Status`. Kind views may show one stable-order row of built-in Group chips; no nested hierarchy or editable user tags exist. Symbols use a dense grid, Kaomoji and short snippets use compact rows/cards, Dividers use wide previews, and Text Art/Frames use monospaced multiline cards.
- A built-in item has stable ID, display name, Kind, content, an optional Popular flag, optional one-line Group of at most 32 UTF-16 units and at most eight unique case-insensitive one-line SearchTerms of at most 24 units each. These additive fields keep catalog schema version 1 and are not present in the My-item editor. The bundled JSON is immutable at runtime, no larger than 1 MiB, contains at most 640 entries, has unique IDs of at most 64 allowlisted characters, uses only known Kinds, limits names to 40 UTF-16 units and content to 512 UTF-16 units and nine explicit lines, and contains valid plain Unicode text with no disallowed control characters. Built-in decorations do not contain supported composition-token syntax. Invalid bundled data makes the picker unavailable with bounded UI feedback; it never blocks startup or output, and there is no duplicate code-owned catalog.
- Favorites are an ordered set of at most 128 built-in or user-item IDs; stale and duplicate IDs are ignored. My items contain stable local ID, Name, Content and one lightweight display type. They are capped at 64 entries; IDs are at most 64 allowlisted characters, names at most 40 UTF-16 units and content at most 512 UTF-16 units/nine explicit lines. There are no editable tags, ratings, recently-used subsystem, inspectors, duplication workflow, cloud sync, sharing or remote catalog.
- Picker activation proposes raw text insertion; it does not create a composition template. Destination semantics remain authoritative, so deliberate token text inserted into Custom is interpreted only by the existing Custom composer. Decorations do not own or persist complete layouts.
- A prospective insertion is measured through the existing composition, alignment and `ChatboxFormatter` path for its originating editor. A per-picker-session cache may reuse that stable calculation. `Only show items that fit` retains only currently insertable entries whose resulting final payload does not truncate. The footer describes the current output after insertion against 144/142 and says Fits, Will be truncated, Not enough editor space, or that the current output is unchanged when the active composition does not consume the edited target. Source art is never silently rewritten or truncated in storage or in the editor. Editor `MaxLength` may reject an insertion; final OSC safety remains solely `ChatboxFormatter`'s responsibility. No second formatter exists.
- Category, My-items, subcategory, search and fit-filter result changes reset the main item viewport to the top after WPF layout. Selection and Favorite/My-item mutations within the same logical view do not request a reset.

- Built-ins may use project-composed short arrangements, requester-provided examples, common short status phrases and individual Unicode symbols without claiming ownership over generic material. Inspiration sites are not content sources. ### Rotating Messages

- Rotation changes only the value supplied to the existing `{message}` token. It never rotates whole templates, adds a `{rotation}` token, or sends output directly. A profile owns one `MessageRotation` with schema version 1, `Enabled`, `IntervalSeconds` and ordered `Items`; each item has stable ID, Text and Enabled. Order is sequential only.
- A profile has at most 16 rotation items. Item IDs are unique within the profile and at most 64 allowlisted characters. Text is plain Unicode, at most 512 UTF-16 units and nine explicit lines. Allowed intervals are exactly 5, 10, 15, 30, 60 and 120 seconds; new/migrated state defaults to 15 seconds. Sub-second intervals, random/weighted order, conditions, schedules, scripts and external data are out of scope.
- The existing profile `Message` field remains only the backward-compatible legacy mirror, never the current runtime rotating value. A v0.6.2 profile with `Message = "Hello!"` loads as a disabled rotation with one enabled item containing exactly `Hello!`; the visible result remains exactly `Hello!` and no automatic rotation starts. Empty Message yields no item. On configuration save only, Message becomes the first enabled configured item's exact text or empty when none is enabled. Timer advancement never writes `DisplayProfile.Message`, `AppSettings.Message`, `settings.json` or `profiles.json`.
- `ProfileLibrary` remains schema version 1 because the optional nested rotation is additive and old JSON remains valid. The nested object carries its own version. Missing rotation migrates in memory deterministically and is serialized on the next ordinary profile save; unrelated profile values and the selected profile are unchanged. A syntactically readable but invalid nested rotation normalizes only that profile's rotation to the safe disabled legacy-Message state. A syntactically unreadable `profiles.json` retains the current whole-library fallback to AppSettings migration; neither case resets AppSettings or unrelated LocalData.
- Runtime timing/index state is per profile and session-only. App launch or first activation starts at the first enabled item with a full interval. Inactive profiles freeze their remaining interval. No current index, deadline or fractional remaining time is persisted.
- Rotation advances only while automatic output is eligible: master Output is On, no Output Pause is active, Manual does not own output, and the effective composition consumes `{message}`. Output Off, Output Pause, Manual ownership, inactive profile and absent `{message}` freeze the remaining interval. Resume continues that remainder; it does not reset or catch up through queued outputs.
- If the app sleeps or stalls while otherwise eligible past a deadline, the runtime advances exactly one item and starts one full interval from the current monotonic time. It never cycles through multiple missed intervals, and composition exposes only that one current value. The existing 1.05-second `ChatboxScheduler` alone owns pacing, dedupe and retry; the rotator has no output dependency and never calls `ChatboxOutput.Send()`.
- Track identity, track changes, lyric changes and lyric timing never reset or advance rotation. Switching profiles activates that profile's frozen state. Zero enabled items supplies the legacy Message fallback (normally empty after a v0.7.0 configuration save) and does not tick. One enabled item is observably identical to today's static Message and does not trigger repeated payloads.
- Editing the current item updates its visible value without resetting its remaining interval. Reordering retains the current item by ID and its remaining interval. Adding an item does not reset. Deleting or disabling the current item selects the next enabled item in post-change order and starts one full interval. Enabling rotation starts at the first enabled item with a full interval; disabling it returns to the deterministic fixed Message mirror. Disabled items are skipped.
- The editor supports add, edit, delete, reorder and per-item enable/disable. Its explicit UI states are none, adding and editing an existing item. A successful add immediately selects and edits that new ID; an invalid add preserves the draft; deletion returns to no selection instead of selecting another row. Removal uses an inline themed confirmation with Cancel/Confirm actions, never a native warning dialog. Decorations can be inserted through the shared picker. The list uses the app's semantic theme resources and remains a small message manager, not a playlist manager.

## Decisions from the native spike
- Apple Music 1.1540 exposes source `AppleInc.AppleMusicWin_nzyj5cx40ttqa!App`. On two observed tracks, `Artist` is `artist — album`, `AlbumTitle` empty and TrackNumber 0. Split only one exact spaced em dash when AlbumTitle is absent; retain raw values.
- Normal playback emits timeline events about every 280ms (sometimes duplicates), with whole-second Position. The sampled timeline age during a 19s playing segment was 0.015–0.280s. Use 250ms fallback polling plus event wakeups, a 2s freshness horizon and a 1.25s quantization/discontinuity tolerance. Paused anchors ignore timestamp age; resume must reject an old paused timestamp until refreshed. These choices need seek and longer end-to-end validation.
- GSMTC TryChangePlaybackPositionAsync returned true for forward/back/restart without changing playback. The product only observes playback; physical seek testing must use Apple Music controls. Do not interpret a successful control call as an observed transition.
- OSC uses a narrow fixed-message encoder (aligned UTF-8 address/type/text with payload-free T/F tags), because this is smaller than a general OSC dependency. OSC format checked against https://opensoundcontrol.stanford.edu/spec-1_0.html ; no third-party implementation copied. UTF-8 is a receiver compatibility requirement beyond the old OSC 1.0 ASCII text wording. A 10s line-hold cap remains provisional. Output pacing was reduced from 1.5s to 1.05s after the user reported 1–2s transition delay. The 2026.2.1 live release documents five messages per five seconds; 1.05s spacing stays below that rate even without relying on the automatic-send exemption: https://docs.vrchat.com/docs/vrchat-202621 . Installed client is 2026.3.2p1. Faster pacing still requires headset validation.
- Follow-up measurement on 2026-09-06 disproved smoothing with max(new anchor, previous interpolated estimate): it added up to 1.083s above Position + LastUpdated age. Replacing every heartbeat anchor then caused visible backward flicker. For repeated integer Position while playing, preserve interpolation only inside that confirmed second; never enter the next second until Windows reports it.
